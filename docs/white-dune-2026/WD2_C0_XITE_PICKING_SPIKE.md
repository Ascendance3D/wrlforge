## 1. Executive result

**Yes, with explicit refusals.** A viewport click can either prove the exact
authored source occurrence the user clicked, or refuse to select anything.

- Ordinary anonymous objects, including the exact WD2-C First Object Box and
  Sphere, identical twins, 12 identical siblings, identical nested structures,
  and 1,000-object grids, are **PROVEN** to the exact source occurrence and
  promoted to their WD2-C Transform where that is provable.
- A Shape that is rendered more than once (DEF/USE anywhere on its ancestor
  chain) is **REFUSED_AMBIGUOUS**. X_ITE's hit carries no instance path, so the
  clicked USE occurrence cannot be proven. That includes the DEF original.
- Inline geometry is **REFUSED_EXTERNAL**. PROTO-instance geometry is
  **UNSUPPORTED**. Geometry under a pointing-device sensor or Anchor is
  **REFUSED_SENSOR_CONFLICT** under the spike's conservative policy.

Measured over 151 graded aimed clicks plus 2 no-geometry controls, 32 coordinate
rows (each through both `touch()` and a real pointer event), and reload and edit
probes: **`WRONG_SOURCE_SELECTIONS = 0`**.

**The cost is private X_ITE API**, in three places (§2). The provenance link
needs a hook on X_ITE's classic-VRML parser, because X_ITE exposes **no** public
source provenance. This is a major design cost that the owner must accept
explicitly before WD2-D.

## 3. X_ITE hit API — measured

`touch(x, y)` returns `true` on a hit. `getHit()` then holds:

| field | meaning (measured) |
|---|---|
| `id` | index into this pass's pointing contexts (transient) |
| `shapeNode` | the **runtime Shape node** (internal object, not an SFNode proxy) |
| `layerNode` | the Layer (always X_ITE's layer0 here) |
| `modelViewMatrix` | the **rendered instance's** model-view matrix (differs per USE instance) |
| `viewMatrix`, `ray`, `point`, `normal`, `texCoord`, `pointer` | geometry of the hit |
| `sensors` | `Map` of pointing-device sensors enclosing the hit Shape |

**There is no path, parent chain, container, instance stack, or source
information in the hit.** A rendered instance is distinguished only by its
matrix. The pointing traverse groups children in a `Set` (:41088), so
`children [ USE A, USE A ]` renders **once** at runtime.

Front-surface semantics hold. The occlusion case P20 returned the front box, and
an edge click returned the back box. The transparent case P21
(`transparency 0.7`) returned the **front transparent** box, with hit point
z = −17.5 in view space, which is the glass front face. In P15, `Switch`
returned only the chosen child, and a click inside the hidden child's
silhouette was **NO_HIT**.

`touch()` returns `false` while the X_ITE viewer is active (mid-navigation,
:71641). WD2-D must treat that as "no selection", not as a miss.

## 4. Source provenance

**What X_ITE exposes about authored source location: NONE.** Runtime nodes carry
no offsets, line/column, token location, or source span. The parser's
`lineNumber` only appears in console warnings, and X_ITE offers no parser
callback.

The parser *internally* holds `this.input` (the exact string) and
`this.lastIndex` (the current offset). The spike obtains provenance by wrapping
`VRMLParser.prototype.nodeStatement` **only while parsing this generation's
exact document string**. The wrapper is gated on `this.input === text`:

1. Call `this.comments()`. This is idempotent; the original calls it first too.
2. Read `start = this.lastIndex`.
3. Call the original.
4. Read `end = this.lastIndex`.
5. Record `{runtimeNode, start, end, kind}`.

Records from PROTO bodies and other execution contexts are dropped. PROTO bodies
are copied per instance, so their nodes are never what gets rendered.

Both offsets come from the parser itself, as indices into the very string it
parsed, so this is provenance and is not inferred from order. They are
UTF-16 code-unit indices, the same unit WRL Forge's AST `range.*.offset` uses.
This was checked with a non-ASCII comment before the first node.

For every node in every fixture, the recorded `[start,end)` equalled the WRL
Forge AST Node `range` exactly. That covers `DEF X` prefixes, which are inside
both ranges, and USE statements, which end after the name in both.

## 7. Anonymous twins — detail

The twins (P5), siblings (P6), and nested twins (P7) are distinguished by
**runtime object identity plus parse-time provenance**, not by geometry, order,
or index. Each anonymous `Shape { geometry Box { } }` is its own runtime object,
and the parser recorded which exact `[start,end)` produced it. The join to the
WRL Forge AST is **exact-span equality at both ends**. An off-by-one span is
UNSUPPORTED (a unit test checks this); it never resolves to the nearest node.

## 8. DEF/USE — detail

A USE occurrence is **not distinguishable** from the hit. All instances return
the same `shapeNode`. The only per-instance datum is `modelViewMatrix`, and
mapping a matrix back to an occurrence would mean recomputing transforms from
source and comparing floats. That is geometric similarity matching, it is
ambiguous for coincident instances, and it is rejected.

The uniqueness test decides refusal. A hit is provable only when the hit Shape
**and every document ancestor** have exactly one source occurrence and exactly
one live runtime document parent. A DEF that is USE'd anywhere fails at that
node, so the DEF original is refused as well. Selecting the DEF "because it owns
the runtime object" would be the wrong-occurrence failure this gate forbids.

A DEF with no USE (P8) is fully provable.

## 9. Inline — detail

Inline geometry's execution context is the Inline's own `X3DScene`, not the
generation's scene. Its `worldURL` is `P16-child.wrl`. That is decided by
object identity (`ctx === generation.scene`), so it is reliable. The
child's text never matches the parse gate, so there is no provenance for it
either. Result: REFUSED_EXTERNAL.

Future work: the exact external document identity (URL) is available, so
switching documents would be a separate lane.

## 10. Sensors and Anchor — detail

| measurement | result |
|---|---|
| `touch()` alone on a TouchSensor'd Shape | `hit.sensors` = {TouchSensor `TS`}. **No** `isOver`/`isActive`/`touchTime` fired |
| a real pointer click on the same Shape | X_ITE's own PointingDevice fired `isOver`, `isActive` true/false, and `touchTime`, independently of the spike |
| `touch()` alone on Anchor geometry | `hit.sensors` = {internal anonymous TouchSensor}. The bound Viewpoint stayed `front` |
| a real pointer click on Anchor geometry | **navigation happened**: the bound Viewpoint became `far` |

So editor picking (`touch`) is inert, and the conflict comes from X_ITE's own
pointer handling acting on the same click. An Anchor whose URL is another world
would **replace the preview world** on an ordinary Model-mode click.

Sunrize's guard (`Document.js:1066`) skips selection when
`getHit().sensors.size > 0`. That protects its own tool handles (PlaneSensor
draggers) and authored sensors.

## 11. Coordinate conversion — measured rule

`touch(x, y)` takes **X_ITE viewport pixels, origin bottom-left**:

```
r  = canvas.getBoundingClientRect();  vp = browser.getViewport();   // [0,0,w,h]
x  = (clientX - r.left) / r.width  * vp[2]
y  = (1 - (clientY - r.top) / r.height) * vp[3]
```

The 32 rows cover these layouts:

- base 800², offset (37,53)
- resize 640×480
- resize 1000×700 + offset
- root font 24 px (a rem-scaled layout, like `--wrl-ui-scale`)
- page zoom 1.5
- `--force-device-scale-factor=2`
- DPR 2 + `contentScale=2` (viewport 1400×1200)

In every row:

- (a) the conversion equalled X_ITE's own `getPointerFromEvent` exactly;
- (b) a real `sendInputEvent` pointer click and a direct `touch()` hit the same
  runtime Shape;
- (c) both were PROVEN to the oracle's object.

Production canvases use the default `contentScale` (1). The viewport then equals
CSS size even at DPR 2, and the rule stays correct when the scale is raised.
WRL Forge UI zoom changes layout, not transforms, so it needs **no special
conversion**. A CSS `transform` on the canvas would break `getBoundingClientRect`
proportionality, and the architecture already forbids one.

Camera navigation is handled inside X_ITE. P22 picks are correct after binding a
rotated, translated Viewpoint.

## 12. Candidate architecture

```
exact text T of preview generation G
   ├─ WRL Forge parse(T) → exact-span index, AST containment, scene tree
   └─ X_ITE createX3DFromString(T) with nodeStatement hook gated on input === T
        → WeakMap_G: runtimeNode → [{start,end,kind}]   (discarded with G)
pointer event → client→viewport rule → touch() → getHit()
   → refusal checks (in order):
       generation ≠ current           → REFUSED_STALE
       no shapeNode                   → no selection
       hit.sensors non-empty          → REFUSED_SENSOR_CONFLICT (policy, §15)
       ctx is another X3DScene        → REFUSED_EXTERNAL
       ctx is a PROTO body            → UNSUPPORTED
       T has syntax errors            → UNSUPPORTED
   → climb runtime parents (getParents) from the Shape; at every node require:
       exactly 1 provenance occurrence          else AMBIGUOUS / UNSUPPORTED
       exactly 1 live document parent, where X_ITE's layer0 Layer/Group are
         excluded BY OBJECT IDENTITY (world.getLayer0()), never by "has no
         provenance"                            else AMBIGUOUS / UNSUPPORTED
   → exact join: each occurrence [start,end) == exactly one AST Node range,
       same node type                           else UNSUPPORTED
   → agreement: runtime chain == AST containment chain, link by link
                                                else UNSUPPORTED
   → logical object: simpleObject.recognize(parent).shape === shape
       ? the Transform : the Shape
   → scene-tree item via sceneTree.itemForAstNode
```

**Where proof comes from:**

- X_ITE's parser says which exact statement produced the object.
- The WRL Forge parse of the same string has exactly one Node with that exact
  span.
- The runtime and source chains agree and have no multiplicity, so that
  occurrence is the only rendered instance.

**Is this the prohibited structural-path identity?** No. Correspondence is never
established by position, order, or index. Each link is independently proven by
its own parser-reported exact span. The chain comparison is a *consistency
check* on two already-proven chains. It is not how anything is matched.

**Preview generation IDs are required.** Each load mints a generation, and a hit
is resolved only against its own generation's map and text. Reload test:
generation-1 hits resolved against generation 2 gave 2/2 REFUSED_STALE. Edit
test: the left twin's translation `-2 0 0` was replaced with `-4.25 0 0` through
the WD1.2 `applyEdits` algebra (Δ = +3). Before and after were PROVEN to the
correct shifted spans. Stale before-edit hits gave 2/2 REFUSED_STALE.

Without the guard, the old offsets in the new text land on
`" [ Shape { geometry Box { "`. They join nothing, but nothing guarantees that
in general.

Production consequences to carry into WD2-D:

- The live preview shows the **last valid scene** on a syntax error, so the
  generation text can differ from the editor buffer. Selection must use the
  generation's text, and is offered to the editor only when it equals the
  current buffer.
- The Mall **Cybertown Fit** preview parses `text + guides`, which is not the
  document string. Picking belongs to the Original rendering only, or must
  refuse.

## 13. Authorable-ancestor (promotion) rule

Promote Shape → Transform **only** when all of these hold:

- the Shape's single proven parent is a Transform;
- `simpleObject.recognize(Transform)` (WD2-C's own source-backed recognizer)
  returns non-null;
- the recognized `.shape` is **the same AST object** as the proven Shape.

Recognition requires exactly one child, a Shape, with an authored, non-USE
Box/Sphere geometry.

Otherwise select the Shape: a Transform with several Shapes (P13), a Group
(P14), a Switch (P15), an Anchor, or a Shape whose geometry is a USE (P11b).
Never climb further, and never "nearest Transform". Sunrize climbs one level
by outline-row structure, keeping the parent when it is any grouping node.
That rule would have collapsed P13's two Shapes into one selection.

|---|---|---|

| **C** per-generation WeakMap | `SAFE_CANDIDATE` *as the container for B* | invalid across reloads (measured), so it must be per generation |

## 15. Policy recommendations (not implemented)

**Sensors and Anchor → Policy D: mode separation.** In Model mode, editor
selection wins. WD2-D must then **suppress X_ITE's own pointer-sensor
dispatch** for the Model viewport (measured: it fires sensors and follows
Anchors on the same click). Authored interaction belongs to an explicit
Play/Preview mode.

If suppression proves impossible without further private API, fall back to
**Policy C**: refuse selection when `hit.sensors` is non-empty, as the spike
does. The beginner cost is that sensor-bearing objects cannot be clicked to
select; they stay selectable from the scene tree.

Policy A alone (select but let sensors fire) is rejected: an Anchor to another
world would replace the preview mid-edit.

**Inline.** Refuse with: *"This object belongs to an external Inline file
(`<name>`) and cannot be selected from this document."* Opening that document is
future work.

**USE.** Refuse when any node on the Shape's chain is multiply referenced, with:
*"This object is drawn by a shared (DEF/USE) node; select the occurrence in the
scene tree."* Never select the DEF as a substitute. A DEF with no USE is
selectable normally.

**Proposed result shape** (derived from §12):

```js
{ status: 'proven' | 'ambiguous' | 'external' | 'sensor-conflict' | 'unsupported' | 'stale' | 'none',
  reason,                 // machine code, e.g. 'runtime-node-referenced-by-several-source-occurrences'
  previewGeneration,
  source: { shape: {start, end, nodeType}, logical: {start, end, nodeType, role: 'shape' | 'simple-object'} } | null,
  sceneTreeItemId: string | null }
```

The result has no runtime object, because it must not outlive the generation.

## 18. WD2-D recommendation

**PROCEED TO WD2-D WITH EXPLICIT REFUSALS.** USE-instanced, Inline, PROTO-instance
and sensor/Anchor hits refuse.

This is conditional on the owner accepting the private-API dependency (§2). If
WD2-D proceeds, it should add a guard test that fails loudly on an X_ITE upgrade
when any of these is missing or changes shape: `VRMLParser.prototype
.nodeStatement`, `comments`, `input`/`lastIndex`, `touch`/`getHit`,
`getParents`, `getWorld().getLayer0()`, or `groupNode`/`groupNodes`. The
spike's harness already throws `PRIVATE_API_MISSING` on the first two.
